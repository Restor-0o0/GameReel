# Архитектура GameReel

Зависимости: платформенные приложения → `app/shared` → `core`.
Дополнительных Gradle-модулей для отдельных экранов нет.

## Core

`core/src/commonMain/kotlin/com/restor/gamereel`:

- `model` — модели и сериализуемые снимки состояния.
- `catalog` — встроенные 40 компонентов и исходные восемь категорий.
- `generator/GeneratorEngine` — выбор тегов, Freeze, Pin, ограничения источников.
- `generator/RandomProvider` — контракт случайного выбора и стандартная реализация.
- `generator/WorkspaceEditor` — операции с барабанами, история, настройки и идеи.
- `generator/CombinationAnalyzer` — явные алиасы механик, правила синергии и индекс
  пар по выбранным библиотекам. Индекс подготавливается при изменении источников,
  отдельно от покадровой анимации. На Web `Dispatchers.Default` не создаёт Web Worker.
- `model/GeneratorPreset` — пресеты и выбор источников. Пользовательские пресеты,
  позиция FAB и снимки источников для отмены сериализуются внутри `Preferences`;
  существующая колонка `preferences_json` сохраняет их без миграции SQLite.
- `repository` — контракт хранения рабочего пространства и библиотек.

Core не зависит от Compose, ViewModel, SQLDelight и файловой системы.
Операции `WorkspaceEditor` возвращают новое состояние без записи в хранилище.
Генератор получает `RandomProvider`, поэтому его можно проверять детерминированно.

## Shared

`app/shared/src/commonMain/kotlin/com/restor/gamereel`:

- `App.kt` — сборка зависимостей, подписка на состояние, тема.
- `navigation` — маршруты, оболочка приложения и связывание действий экранов.
- `presentation` — состояние приложения и ViewModel с последовательной очередью изменений.
  Преобразование результатов импорта и ошибок в тексты находится в `GameReelMessages.kt`.
- `feature/generator` — барабаны, карточки, слот-машина и анимация.
  `SlotMachine` собирает корпус и управление; `SlotReelGrid` раскладывает барабаны,
  `SlotReel` отображает ячейку, `SlotLever` рисует рычаг, `RollingValue` прокручивает значения.
  В режиме автомата `RollingArtwork` рисует видимые элементы в Canvas: прогресс
  читается только при отрисовке, символы измеряются заранее. В режиме карточек
  текстовая лента перемещается через `graphicsLayer` без покадровой раскладки.
  Панель действий экрана и её локальное состояние меню находятся в `GeneratorToolbar`.
- `feature/search`, `library`, `ideas`, `settings` — остальные экраны.
  Диалог создания и редактирования идеи находится в `feature/ideas/IdeaDialog.kt`.
  В поиске карточки `GameResult` / `TagResult` и диалог `GameDetails` отделены от экрана.
  Подготовка списка игр кэшируется по библиотекам; фильтрация предшествует удалению
  дубликатов, чтобы находились разные названия одной Steam-игры в разных источниках.
- `ui/components`, `ui/theme`, `ui/presentation` — общие компоненты, оформление и описания тегов.
- `data/storage` — SQLDelight, браузерное хранилище и настройки сериализации.
- `data/importer` — преобразование JSON библиотек в модели.
- `data/bundled` — загрузка и обновление встроенных библиотек.

Экраны получают данные и callbacks. Они не читают ViewModel и хранилище напрямую.

Чтение и декодирование картинок выполняются через `Dispatchers.Default`.
Кэш изображений обслуживается UI-корутинами, ограничен 96 записями и запоминает
отсутствующие файлы. Mutex сериализует загрузки и предотвращает повторное декодирование
одного файла; отмена загрузки распространяется как `CancellationException`.
В браузере `Dispatchers.Default` сам по себе не создаёт отдельный Web Worker.
ViewModel применяет операции `WorkspaceEditor` и публикует результат только после успешного сохранения.
Ошибка записи оставляет прежнее состояние видимым.

Платформенные фабрики находятся в `androidMain`, `iosMain`, `jvmMain`, `jsMain`, `wasmJsMain`,
в пакете `data.storage`. SQLite используется на Android/iOS/Desktop, localStorage — в браузере.
Точки входа Android/Desktop/Web/iOS только запускают общий интерфейс.

## Сохранение и обновления

`Preferences.language` хранит выбор системного, русского или английского языка.
В старых сохранениях поле отсутствует и получает значение `SYSTEM`.
`text/AppLanguageProvider` задаёт среду ресурсов только внутри приложения, не меняя
локаль процесса. Адаптер изолирует внутренний provider Compose Resources 1.12.1;
при обновлении этой зависимости нужно проверить его совместимость.
Индекс поиска получает ту же среду ресурсов и пересоздаётся при смене языка.
Переводы описаний базовых тегов находятся в XML; тексты библиотек без перевода
остаются на исходном языке.

SQLite остаётся на схеме v2. Имена таблиц и ключи localStorage не изменены.
Идеи, текущие барабаны и история хранят снимки тегов независимо от библиотек.
Обновление набора заменяет только его справочные игры и теги.

Встроенные наборы обновляются по версии из `data/bundled/BundledLibraries.kt`:
Steam и Google Play — v7, авторские теги — v10. Равная или более новая
установленная версия сохраняется. Идентичность игры определяется источником и external ID,
тега — игрой, категорией и нормализованным названием, а не позицией в списке.

«Сбросить барабаны» создаёт исходные восемь категорий и новый результат из активных источников.
Настройки, идеи и счётчик ID сохраняются; прежние барабаны попадают в историю для отмены.

## Библиотеки

Исходные снимки и скрипты находятся в `tools/library_sources`. В приложение попадают JSON
из `app/shared/src/commonMain/composeResources/files/libraries`.

```powershell
python tools/build_bundled_libraries.py
```

Команда применяет правила и правки из `tools/library_sources` к локальным данным.
Она не скачивает новые рейтинги. Недостающие Steam tags можно взять из второго Steam-набора
только при точном совпадении appid. Google Play использует категорию, название и локальный
кэш метаданных, если он есть. Разметка эвристическая; неизвестные поля остаются пустыми.
Отчёты покрытия записываются в `tools/library_sources/*/data/tag_coverage_report.json`.

Авторский набор хранится отдельно в `curated.json`. Поле `Library.standaloneTags`
содержит теги без `sourceGameId`; `LibraryPack.allTags` объединяет их с тегами игр.
В SQLite это поле сериализуется в существующий `metadata_json`, поэтому новая миграция
схемы не нужна. Старые метаданные без этого поля читаются с пустым списком.

При Spin сначала равновероятно выбирается уникальное название тега, затем его игровой
референс. Число игр с одним тегом не увеличивает вероятность этого тега.

## Проверка

Замеры плавности слот-машины и команды для повторной проверки:
[SPIN_PERFORMANCE.md](SPIN_PERFORMANCE.md).

Тесты повторяют пакеты исходников: генерация и операции — в core; импорт, хранение,
обновление библиотек и последовательность сохранений — в shared.

```powershell
.\gradlew.bat :core:jvmTest :app:shared:jvmTest :app:androidApp:assembleDebug
.\gradlew.bat :app:desktopApp:compileKotlin :app:webApp:compileKotlinJs :app:webApp:compileKotlinWasmJs
```

iOS собирается через Xcode на macOS.
