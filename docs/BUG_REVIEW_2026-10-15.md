## Исходное ревью

Проверены генерация и история, пресеты, импорт, оба хранилища, восстановление
бэкапов, сохранение идей и фильтрация проектов. Код приложения в рамках этого
ревью не изменялся. P1 — риск потери пользовательских данных; P2 — функциональный
дефект, требующий исправления.

Шесть проблем воспроизведены отдельными JVM-тестами. Ещё две установлены по
обработчикам интерфейса; их полное воспроизведение на устройстве не завершено.

## 1. P1: восстановление бэкапа может частично перезаписать данные при ошибке

Место: `app/shared/src/commonMain/kotlin/com/restor/gamereel/presentation/GameReelViewModel.kt:98`.

Сценарий: восстановить бэкап, заменяющий существующую пользовательскую библиотеку,
и получить ошибку записи рабочего пространства, например из-за заполненного диска.
`importLibrary` уже заменил библиотеку, а следующий `save` завершился ошибкой.
Пользователь видит сообщение о неудаче и старое состояние интерфейса, но прежняя
библиотека в хранилище уже потеряна. Ошибка на второй библиотеке также оставляет
первую заменённой. SQL-транзакция охватывает только одну библиотеку, не всё восстановление.

Подтверждение: `failedRestoreMustNotReplaceExistingLibrary` — после ошибки записи
в хранилище остаётся `Replacement` вместо `Original`.

Исправление: операция восстановления должна быть атомарной для библиотек и рабочего
пространства; для браузерного хранилища нужна запись подготовленного полного снимка
либо механизм отката. Публиковать новые данные после успешного завершения операции.

## 2. P2: фильтр исчезнувшего проекта скрывает остальные идеи

Место: `app/shared/src/commonMain/kotlin/com/restor/gamereel/feature/ideas/SavedIdeasScreen.kt:81`.

Сценарий: есть идея в проекте A и идея без проекта. Выбрать A и удалить его последнюю
идею либо очистить у неё поле проекта. `selectedProject` остаётся равным A,
`visibleIdeas` становится пустым, а `projects` — пустым. Вместе с панелью проектов
исчезает кнопка «Все проекты». Остальные идеи сохранены, но экран показывает пустой
список без возможности сбросить фильтр. Переход на другой экран и обратно сбрасывает
локальное состояние и возвращает идеи.

Подтверждение: анализ вычисления списка и условия отображения панели; сценарий на
планшете подготовлен, но финальные действия не выполнены из-за потери подключения.

Исправление: сбрасывать выбранный проект, когда его больше нет в списке, либо всегда
оставлять доступным сброс фильтра.

## 3. P2: ошибка сохранения идеи уничтожает введённый черновик

Место: `app/shared/src/commonMain/kotlin/com/restor/gamereel/navigation/GameReelScreen.kt:296`.

После нажатия «Сохранить» диалог сразу закрывается (`saveIdea = false` или
`editing = null`), хотя ViewModel только ставит запись в очередь. При ошибке записи
рабочее пространство корректно остаётся прежним, но введённые название, заметки и
концепция находились в локальном `remember` закрытого диалога. Их нельзя повторно
сохранить после устранения ошибки; текст приходится вводить заново.

Подтверждение: анализ жизненного цикла диалога и асинхронного обработчика сохранения.
Это отдельная проблема от защиты уже сохранённых данных, которую проверяет
`failedSaveDoesNotPublishUnsavedState`.

Исправление: закрывать диалог по подтверждению успешного сохранения, сохранять черновик
при ошибке и блокировать повторную отправку, пока первая запись выполняется.

## 4. P2: принятый импорт с ID встроенной библиотеки исчезает в веб-версии

Место: `app/shared/src/commonMain/kotlin/com/restor/gamereel/data/storage/BrowserWorkspaceRepository.kt:30`.

Сценарий: импортировать JSON с ID `curated_v5` и версией не ниже установленной.
Импортёр и ViewModel допускают такую замену. Однако браузерный репозиторий считает
любую библиотеку с этим ID временной и хранит её только в памяти. После перезагрузки
страницы пользовательская версия исчезает, загружается поставляемый каталог.
В бэкап такой импорт тоже не попадает, поскольку исключается по встроенному ID.

Подтверждение: `importedBuiltinIdMustSurviveBrowserRestart` — библиотека есть до
создания нового экземпляра репозитория и отсутствует после него.

Исправление: отделить загрузку поставляемых наборов от пользовательского импорта.
Либо сохранять пользовательские переопределения, либо явно отклонять занятые ID
при импорте до сообщения об успехе.

## 5. P2: валидатор бэкапа допускает повторное использование ID

Место: `app/shared/src/commonMain/kotlin/com/restor/gamereel/data/storage/WorkspaceBackup.kt:17`.

Сценарий требует повреждённого или отредактированного бэкапа: в нём уже есть
`idea:1`, а `nextId` равен 1. Проверка принимает файл, поскольку проверяет лишь
положительность счётчика и уникальность существующих идей. Следующее сохранение
создаёт вторую `idea:1`. В SQL это нарушает первичный ключ `saved_ideas`; сохранение
откатывается, и последующие попытки повторяют ту же ошибку. В браузере дубли остаются
в списке и конфликтуют с ключами элементов интерфейса.

Подтверждение: `backupMustRejectAnIdCounterThatWillReuseAnExistingIdeaId` — бэкап
принимается, а следующее создание идеи действительно повторяет ID.

Исправление: проверить или безопасно пересчитать следующий ID с учётом идей,
барабанов, пресетов, фильтров и снимков истории до восстановления.

## 6. P2: экспортированный приложением набор тегов может не импортироваться обратно

Место: `core/src/commonMain/kotlin/com/restor/gamereel/generator/WorkspaceEditor.kt:206`.

Сценарий: импортировать библиотеку с игрой, содержащей 101 тег, создать из неё набор
и экспортировать JSON набора. Эти действия разрешены. Обратный импорт набора падает
на `game.tags.size <= 100`: такого ограничения нет ни в импорте библиотеки, ни в
сохранении набора. Файл создаётся самим приложением, но другой экземпляр приложения
его не принимает. Аналогичное ограничение есть в валидации библиотек внутри бэкапа.

Подтверждение: `anExportedTagSetMustPassItsOwnImporter` использует настоящий
`JsonLibraryImporter`, сохранение набора и сериализацию/десериализацию его JSON.

Исправление: согласовать ограничения на входе, при создании наборов и при обратном
импорте; не позволять экспортировать состояние, которое приложение не поддерживает.

## 7. P2: отмена сброса не восстанавливает связь варианта с исходной идеей

Место: `core/src/commonMain/kotlin/com/restor/gamereel/generator/WorkspaceEditor.kt:105`.

Сценарий: начать вариант сохранённой идеи → сбросить барабаны → отменить сброс →
сохранить результат. Барабаны восстанавливаются, но `activeVariantParentId` уже
очищен сбросом. История его не хранит, поэтому результат сохраняется как независимая
идея и теряет связь для сравнения вариантов.

Подтверждение: `undoResetMustRestoreVariantLineage` — после отмены барабаны совпадают
с исходными, но ID родительской идеи заменён на `null`.

Исправление: включить контекст варианта в снимок отменяемой операции.

## 8. P2: сохранение текущего пресета молча не работает при 20 барабанах

Место: `core/src/commonMain/kotlin/com/restor/gamereel/generator/WorkspaceEditor.kt:143`;
интерфейс: `app/shared/src/commonMain/kotlin/com/restor/gamereel/feature/generator/PresetsDialog.kt:118`.

На экране генератора можно добавить 20 и более барабанов. «Сохранить текущие» остаётся
доступным, но `saveReelPreset` при количестве больше 19 возвращает исходное состояние.
Интерфейс очищает имя и закрывает форму без сообщения, а пресет не появляется.

Подтверждение: `savingTheCurrentTwentyReelsMustNotSilentlyDiscardThePreset` — двадцать
барабанов созданы обычными операциями редактора, после сохранения пресетов всё ещё ноль.

Исправление: согласовать лимит с генератором либо отключить сохранение с понятным
объяснением; возвращать типизированную ошибку вместо незаметного пропуска операции.
