# Idea Slot Machine — генератор игровых концептов

Версия: 0.1  
Цель: быстрый генератор идей для небольших Steam-игр, где каждая строка — отдельный «барабан». Пользователь крутит только незамороженные строки, добавляет свои варианты и изображения, удаляет ненужные барабаны и сохраняет удачные комбинации.

## 1. Базовая идея интерфейса

Экран состоит из вертикального списка строк-барабанов. В каждой строке слева показан тип барабана, в центре — выпавшая карточка, справа — действия.

Для каждой строки нужны кнопки:

- **Lock / Freeze** — строка остаётся неизменной при следующем Spin.
- **Reroll row** — перекрутить только эту строку.
- **Remove** — убрать барабан из текущей схемы.
- **Edit pool** — открыть список вариантов этого барабана, менять веса, отключать элементы, добавлять свои.

Общие действия:

- **SPIN** — перекручивает только незамороженные строки.
- **Unlock all** — снять все замки.
- **Add reel** — добавить новый барабан из шаблонов или создать собственный.
- **Save idea** — сохранить комбинацию как карточку идеи.
- **History** — последние 50 комбинаций.
- **Mode** — `Wild / Balanced / Production Safe`.
- **Scope filter** — микро / 1 месяц / 3–4 месяца / 6–12 месяцев.

Ключевое правило UX: после Spin пользователь должен за 3–5 секунд понять выпавший концепт без чтения длинного текста.

## 2. Рекомендуемые барабаны

### КОР

Главное действие, которое игрок делает постоянно. Примеры: стрельба, уборка, рыбалка, добыча ресурсов, физическая переноска предметов, платформинг, проверка документов, производство, готовка, торговля.

Это обязательный барабан. Обычно выбирается один элемент.

### ДОП. МЕХАНИКА

Вторая система, которая меняет кор: строительство, крафт, инвентарь-пазл, сотрудники, транспорт, отношения, коллекционирование, скрытность, таймер, автоматизация, случайные события.

Можно разрешить 0–2 дополнительных механики.

### СТРУКТУРА

Определяет, как игра нарезана во времени:

- забеги;
- уровни;
- открытый мир;
- хаб + миссии;
- смены / рабочие дни;
- одна большая локация;
- песочница;
- линейная кампания.

### ПРОГРЕССИЯ

Что остаётся после игровой сессии:

- деньги + магазин;
- мета-апгрейды;
- лут и билды;
- техдерево;
- коллекция;
- новые персонажи/инструменты;
- сюжетные открытия;
- ничего — чистая skill-based игра.

### ДАВЛЕНИЕ / ОГРАНИЧЕНИЕ

Обычно именно этот барабан превращает спокойный кор в игру:

- таймер;
- дефицит ресурса;
- маленький инвентарь;
- усиление угрозы;
- день/ночь;
- риск/награда;
- одна ошибка сильно портит ситуацию;
- вообще без давления.

### ИГРОКИ

- Solo;
- Co-op 2–4;
- Co-op 4–8;
- локальная party-игра;
- соревновательная.

Для режима `Production Safe` лучше по умолчанию давать больший вес Solo и Co-op 2–4.

### КАМЕРА

Первое лицо, третье лицо, top-down, side-view, isometric, fixed screen, UI/table, desktop overlay, free camera.

### ГРАФИКА

Отдельный барабан обязателен. Важно хранить не название игры, а именно производственный стиль:

- low-poly 3D;
- low-poly + современный свет;
- PSX / gritty low-poly;
- voxel 3D;
- stylized 3D;
- cartoon 3D;
- realistic 3D;
- pixel art 2D;
- expressive pixel art;
- hand-drawn 2D;
- flat/vector 2D;
- watercolor / painterly;
- minimalist geometric;
- 1-bit / limited palette;
- anime 2D;
- mixed 2D/3D.

Графика должна иметь параметры `dimension`, `complexity`, `animation_cost`, `asset_reuse`, чтобы генератор мог учитывать scope.

### СЕТТИНГ

Фабрика, офис, магазин, космос, данж, море, маленький город, лес, заброшенный район, корабль, лаборатория, обычное бытовое место и т.п.

### ТВИСТ

Самый полезный барабан для оригинальности. Он не задаёт жанр, а меняет правило:

- менеджмент, но всё делаешь руками;
- инструмент одновременно служит перемещением;
- две разные петли кормят друг друга;
- каждый враг — отдельное правило;
- провал тоже награда;
- вся игра вокруг одного объекта;
- прогресс только через знания;
- обычная работа становится опасной;
- всё построено на физике;
- игра ломает собственный интерфейс.

### СКОУП

Не механика, а ограничитель генератора. Особенно полезен для идей, которые надо реально сделать:

- микро-прототип;
- ~1 месяц;
- ~3–4 месяца;
- 6–12 месяцев.

При выбранном `3–4 месяца` режим `Production Safe` должен уменьшать вес больших открытых миров, сложной сетевой физики, VR и огромного количества уникального контента.

## 3. Как должна работать заморозка

У каждой строки есть `locked: bool`. Нажатие Spin проходит только по `locked == false`.

Хороший сценарий:

1. Выпало `физическая уборка + кооп + low-poly`.
2. Пользователю нравится кор и графика — он их замораживает.
3. Несколько раз перекручивает только `сеттинг`, `твист` и `давление`.
4. Получает `заброшенная космическая станция + ограниченный кислород + предметы надо физически выносить`.
5. Сохраняет как идею.

Именно такой итеративный поиск важнее полностью случайного Spin.

## 4. Пользовательские элементы

Каждый элемент пула:

```json
{
  "id": "my_factory_cleaning",
  "label_ru": "уборка производственной линии",
  "description_ru": "грязь мешает машинам и портит продукт",
  "weight": 3,
  "enabled": true,
  "image": "custom/factory_cleaning.png",
  "tags": ["manual-work", "factory", "physics"],
  "scope_cost": 1
}
```

Поддержать:

- текст без изображения;
- текст + локальное изображение;
- drag&drop картинки;
- вставку из буфера;
- импорт/экспорт JSON;
- пользовательские категории барабанов;
- веса 1–10;
- временное отключение элемента без удаления.

## 5. Карточки игр-референсов

В архиве есть `games_1000.json/csv`. Это не отдельный обязательный барабан, а библиотека примеров.

У карточки игры показывать:

- header/cover;
- название;
- кор-механики;
- дополнительные механики;
- визуальный стиль;
- камеру;
- примерный production scope;
- короткую заметку «что отсюда полезно взять как принцип».

Нажатие на механику в карточке может добавить её в соответствующий барабан. Рядом с каждым атомом также должна быть команда **`+ Pin` / `Добавить замороженным`** — она безусловно добавляет выбранный тег как отдельный закреплённый барабан слева; подробнее в разделе 12.

## 6. Три режима генерации

### Wild

Почти чистый random. Нужен для странных сочетаний.

### Balanced

Мягкие веса совместимости. Например `рыбалка + ограниченный инвентарь` получает небольшой бонус, но запретов почти нет.

### Production Safe

Главная задача — не выдать концепт на три года разработки, если выбран scope 3–4 месяца. Система не обязана запрещать дорогую механику, но должна предупреждать и снижать её вероятность.

## 7. Не делать «умный AI-генератор» обязательным

Первая версия должна работать полностью детерминированно на JSON-пулах. AI можно добавить потом отдельной кнопкой `Develop this idea`, которая получает уже выпавшую комбинацию и предлагает 3 варианта core loop.

Так генератор остаётся быстрым, предсказуемым и дешёвым.

## 8. Модель состояния

Минимально:

```text
GeneratorState
  reels[]
    id
    label
    locked
    pinned
    positionGroup   // pinned-left | normal
    source          // optional: game AppID/name/aspect
    enabled
    selectedItem
    pool[]
  mode
  scope
  history[]
  savedIdeas[]
```

Сами данные барабанов не должны быть захардкожены в UI. Всё читается из `reels.json` + пользовательского файла.

## 9. Что сделать в MVP

MVP уже полезен, если есть:

- вертикальные строки-барабаны;
- Spin;
- lock каждой строки;
- reroll одной строки;
- add/remove reel;
- редактирование пула;
- пользовательские текст/картинки;
- сохранение комбинаций;
- `+ Pin` любого тега/аспекта из библиотеки игр с мгновенным появлением замороженного барабана слева;
- история;
- импорт/экспорт JSON;
- библиотека 1000 игр;
- локальные Steam-картинки после запуска downloader-скрипта.

Не нужны на старте аккаунты, облачная синхронизация, AI, сложный backend и социальные функции.


## 10. Барабан ИГРА-РЕФЕРЕНС для базы 1000

Для большой базы стоит добавить отдельный reel `reference_game`. Карточка показывает Steam header, название, жанр и 3–8 атомов механик. Можно заморозить игру-референс отдельно от остальных барабанов. Дополнительно полезен режим “Extract one aspect”: взять из выпавшей игры только кор, только графику, только камеру или один тег. Это не заставляет концепт копировать всю игру целиком.

## 11. Reference Spin — генерация через 2–3 игры-референса

Это отдельный режим поверх обычных атомарных барабанов. Он нужен для случаев, когда проще мыслить не абстрактными тегами, а конкретными играми.

### Как работает

Генератор случайно выбирает 2–3 игры из базы `games_1000.json`. Для каждой выбранной игры отдельно определяется, **что именно из неё использовать как источник вдохновения**:

- `CORE` — главное повторяемое действие;
- `SECONDARY` — дополнительная механика;
- `STRUCTURE` — структура сессии / забега / смены / открытого мира;
- `PROGRESSION` — способ развития игрока;
- `PRESSURE` — таймер, риск, дефицит, нарастающая угроза;
- `VISUAL` — производственный визуальный стиль;
- `CAMERA` — способ подачи пространства;
- `SETTING` — тип окружения/фэнтези;
- `INTERACTION` — характер взаимодействия: физика, UI, прямое управление, автоматизация и т.п.

Пример результата:

```text
Reference A: Teardown
Take: INTERACTION -> физическое разрушение окружения

Reference B: Stardew Valley
Take: STRUCTURE -> день как ограниченная рабочая сессия

Reference C: DREDGE
Take: PRESSURE -> безопасный день / опасная ночь

Result seed:
«Игра про ручную разборку аварийных объектов, где за рабочий день надо успеть
демонтировать и вынести ценные части, а после наступления ночи территория
становится значительно опаснее».
```

Важно: режим не должен говорить «смешай игру A и игру B». Он вытаскивает **один принцип из каждой игры**, чтобы результат не превращался в прямое копирование.

### Интерфейс

Каждый референс показывается отдельной карточкой:

```text
[ image ]  Teardown
           TAKE: Interaction
           физическое разрушение

           [ Freeze game ]
           [ Freeze aspect ]
           [ Reroll aspect ]
           [ Reroll game ]
```

Нужно два независимых замка:

- **Freeze game** — оставить игру, но разрешить менять аспект, который из неё берётся;
- **Freeze aspect** — оставить тип аспекта (`CORE`, `VISUAL` и т.д.), но разрешить менять игру.

Это важнее одного общего Lock. Например, пользователь может решить: «Мне точно нужна графика из этой игры, но остальные два референса надо перекрутить».

### Количество референсов

По умолчанию — 3.

Разрешить пользователю выбирать:

- 1 — почти чистый референсный анализ;
- 2 — простое смешивание;
- 3 — основной режим;
- 4–5 — хаотичный brainstorm.

Больше 5 по умолчанию не нужно: идея начинает терять читаемый кор.

### Связь с обычными барабанами

После Reference Spin кнопка `Extract to reels` должна разложить выбранные принципы по обычным барабанам.

Например:

```text
Teardown / interaction  -> ДОП: разрушение окружения
DREDGE / pressure       -> ДАВЛЕНИЕ: безопасный/опасный цикл
Stardew / structure     -> СТРУКТУРА: рабочие дни
```

После этого пользователь продолжает обычный процесс: замораживает понравившееся и перекручивает остальные строки.

### Anti-copy правило

Если из одной игры уже взят `CORE`, генератор должен снижать вероятность одновременно взять из неё же `STRUCTURE + SETTING + VISUAL`. Чем больше аспектов копируется из одного источника, тем сильнее штраф.

Практическое правило для MVP:

```text
1 aspect from game  -> no penalty
2 aspects           -> weight x0.5
3+ aspects          -> weight x0.15 + warning
```

Предупреждение может выглядеть так:

> Слишком много признаков происходит из одного референса. Перекрути хотя бы один аспект, если хочешь получить более самостоятельную концепцию.

### Почему режим полезен

Steam-теги хорошо дают широкую случайность, но часто слишком абстрактны. Конкретная игра несёт связку решений: темп, ощущение управления, структуру пространства, масштаб объектов и визуальную читаемость. Reference Spin позволяет использовать эту связку, не перетаскивая игру целиком.

Для генератора стоит оставить оба подхода:

- **Atomic Spin** — максимальная комбинаторика;
- **Reference Spin** — более понятные и интерпретируемые источники вдохновения;
- **Hybrid Spin** — 1–2 референса + несколько обычных барабанов.

## 12. Безусловное добавление тега — Pin as frozen reel

Это быстрый ручной путь, который работает **в обход рандома и правил совместимости**. Он нужен для ситуации: пользователь листает библиотеку из 1000 игр, находит конкретную механику, визуальный приём, камеру, структуру или другой атом и уже точно знает, что хочет оставить его в концепте.

### Базовый сценарий

1. Пользователь открывает карточку игры, например `Teardown`.
2. Видит атом `INTERACTION -> разрушение окружения`.
3. Нажимает рядом `+ Pin` / `Добавить замороженным`.
4. Слева от обычных барабанов мгновенно появляется отдельный барабан:

```text
[🔒] INTERACTION
     Разрушение окружения
     source: Teardown
     [Unlock] [Remove]
```

5. Этот барабан **не меняется** при `Spin`, `Reroll all`, смене `Wild / Balanced / Production Safe` и повторных `Reference Spin`.
6. Пользователь может таким же образом закрепить ещё несколько вещей из любых других игр.
7. Все незакреплённые барабаны продолжают крутиться уже вокруг выбранного вручную ядра.

### Что можно закреплять

Команда должна быть доступна для любого атома, который система умеет показать:

- `CORE`;
- `SECONDARY`;
- `STRUCTURE`;
- `PROGRESSION`;
- `PRESSURE`;
- `PLAYERS`;
- `CAMERA`;
- `VISUAL` / графика;
- `SETTING`;
- `INTERACTION`;
- отдельный Steam tag;
- пользовательский тег или собственная идея.

То есть пользователь не обязан ждать, пока нужная штука случайно выпадет на барабане.

### Расположение

Закреплённые вручную барабаны образуют отдельную группу **`Pinned` слева** от случайных барабанов.

```text
PINNED                         RANDOM REELS
┌──────────────────────┐       ┌───────────────┐
│ 🔒 Physics destruction│       │ CORE          │
├──────────────────────┤       ├───────────────┤
│ 🔒 Low-poly visual    │       │ STRUCTURE     │
├──────────────────────┤       ├───────────────┤
│ 🔒 First person       │       │ PRESSURE      │
└──────────────────────┘       └───────────────┘
```

Группа должна визуально отделяться, чтобы было понятно: это **условия пользователя**, а не случайный результат.

### Поведение Pin

`Pin` означает более сильное состояние, чем обычный `Freeze`:

- `Freeze` фиксирует текущее случайно выпавшее значение;
- `Pin` вручную добавляет новое обязательное значение в концепт;
- `Spin` никогда не снимает `Pin`;
- `Unlock all` по умолчанию снимает только обычные Freeze и **не трогает Pin**;
- для снятия Pin нужна явная команда `Unpin` или `Remove`.

Опционально можно добавить отдельную кнопку `Unpin all`.

### Дубликаты

Если пользователь пытается второй раз закрепить точно тот же атом, не создавать копию. Вместо этого подсветить уже существующий pinned-барабан.

Если текст совпадает, но источник другой, считать одинаковыми атомы с одинаковым нормализованным `atom_id`. Источник при этом можно хранить списком:

```text
Разрушение окружения
Sources: Teardown, Noita
```

### Добавление из карточки игры

В карточке игры каждый тег/аспект становится интерактивным:

```text
Teardown

CORE
Demolition jobs                 [+ Pin]

INTERACTION
Physics destruction             [+ Pin]

CAMERA
First person                    [+ Pin]

VISUAL
Stylized voxel / low-poly       [+ Pin]
```

Также полезен multi-select режим:

```text
[x] Physics destruction
[x] First person
[ ] Mission structure
[x] Voxel visual

[ Add 3 as pinned reels ]
```

Это позволяет быстро разобрать найденную игру на нужные части, не используя Reference Spin вообще.

### Добавление из поиска

Поиск по библиотеке должен искать не только игры, но и атомы. Например пользователь вводит `physics`, открывает результаты и может сразу нажать `+ Pin` у нужной строки.

Фильтры поиска:

```text
All | Core | Mechanics | Structure | Progression | Visual | Camera | Setting | Tags
```

Так библиотека 1000 игр становится ещё и каталогом механик/визуальных решений.

### Модель данных

Pinned reel можно хранить тем же объектом, что и обычный барабан, но с дополнительными полями:

```json
{
  "id": "pinned_interaction_physics_destruction",
  "label": "INTERACTION",
  "locked": true,
  "pinned": true,
  "positionGroup": "pinned-left",
  "selectedItem": {
    "id": "physics_destruction",
    "label_ru": "разрушение окружения",
    "source": {
      "type": "steam_game",
      "app_id": 1167630,
      "game": "Teardown",
      "aspect": "INTERACTION"
    }
  },
  "pool": []
}
```

Для pinned-барабана `pool` может быть пустым: он не участвует в случайном выборе.

### Unpin и превращение в обычный барабан

У pinned-барабана нужны три действия:

- `Unpin` — оставить значение на экране, но разрешить следующему Spin заменить его;
- `Remove` — полностью убрать условие;
- `Move to reel` — добавить атом в пул соответствующего обычного барабана и удалить pinned-строку.

`Unpin` удобно реализовать как превращение pinned reel в обычный locked reel, после чего пользователь сам решит, когда его разморозить.

### Связь с генерацией

Pinned-барабаны являются **жёсткими входными условиями** для всех режимов. Например:

```text
PINNED:
- CORE: управление магазином
- VISUAL: PS1-style 3D
- CAMERA: first person

SPIN:
- STRUCTURE -> короткие смены
- PRESSURE -> очередь клиентов
- TWIST -> магазин находится на движущемся поезде
```

Так генератор превращается не только в рулетку, но и в инструмент «я уже знаю 2–3 вещи, придумай мне всё остальное».

### Сохранение идеи

При сохранении комбинации pinned-условия должны храниться отдельно от случайно выпавших значений:

```json
{
  "pinned": ["store_management", "ps1_3d", "first_person"],
  "generated": ["shift_structure", "customer_queue", "moving_train"],
  "seed": 19384721
}
```

Это позволит позже открыть идею и перекрутить только сгенерированную часть, сохранив исходный замысел пользователя.
